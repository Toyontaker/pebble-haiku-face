# Haiku — その時の季節と天気を詠む Pebble ウォッチフェイス

LLM（Claude・ChatGPT・Gemini）が朝・昼・夜ごとに詠んだ俳句を、短冊と筆の和風デザインで表示するウォッチフェイスです。
日付、時間帯、日の出との関係、二十四節気、月齢、市区レベルの地名、体感の天気、歩数、平日か休日か、そして直前に詠んだ句をプロンプトに埋め込みます。条件が動くたびに句も変わります。

- 日本語モード: 短冊に縦書き3行（右から左、上中下を少しずらす伝統的な三行書き）
- 英語モード: 横書き3行（長い行は自動折り返し）
- 上部の帯に時刻と日付・曜日。時刻は筆文字（楷書・行書・太字）とデジタルから選択
- 日付・曜日は時刻の右に大きく表示。basalt 系（144px 幅）は「9/6」「日曜」の2段 18px、emery（200px 幅）は「9/6(日)」の1段 24px。時刻と重なる日は自動で一段小さくなる
- 紙の隅に日付入りの落款（赤い印）
- 背景は日の出・日の入りに連動。日中と夜それぞれに、季語にちなんだ色とモチーフを選べる
- 俳句は腕時計側に保存されるため、スマホ未接続時も前回の句を表示
- 天気は Open-Meteo、地名は BigDataCloud から取得（いずれも APIキー不要）

## 対応機種

basalt / chalk / diorite / emery / flint / gabbro（Pebble Time 系、Pebble 2、Time 2、Pebble 2 Duo、Round 2）。
設定画面は pebble-clay の後継の @rebble/clay で作っています（pebble-clay は flint / gabbro を未サポートのため乗り換えた）。
丸画面（chalk 180px・gabbro 260px）の配置は chalk を基準に画面幅に比例させています。gabbro は時刻帯を比例より詰め、その分だけ短冊を縦に伸ばして、縦書きでも 24px の字が使えるようにしています。flint は diorite と同じ 144×168 の白黒画面で、そのまま同じ配置です。見本は `screenshots/gabbro_ja_day.png`・`gabbro_en_day.png`・`flint_en_day.png` です。

日本語の表示は、端末にインストール済みの日本語フォント（システムフォント置き換え）に依存します。
アプリ側にフォントは同梱していません。言語パックを入れていないエミュレータでは日本語が □ で表示されます。
`screenshots/` の画像は、エミュレータに言語パックを適用して撮影したものです（手順は下記）。

## セットアップ

1. ビルドしてインストール

   ```
   cd ~/haiku-face
   pebble build
   pebble install --phone <スマホのIP>
   ```

2. Pebble アプリのウォッチフェイス一覧から「Haiku」の設定（歯車）を開く
3. 使用する LLM、API キー、言語を設定して保存

## 思考の深さと費用

「思考の深さ」は LLM が答える前にどれだけ考えるかの設定で、費用と待ち時間に直結します。俳句1句あたりの思考トークン数の実測です（Gemini、2026年9月）。

| 設定 | gemini-flash-latest | gemini-3.8-flash | gemini-pro-latest |
|---|---|---|---|
| 低 | 0 | 0 | 213 |
| 中 | 352 | 261 | 522 |
| 高 | 791 | 1289 | 990 |

俳句では「低」でも十分な句が返るため、既定は「低」です。Claude には `thinking: {type: "adaptive"}` と `output_config.effort` を付けます（effort だけでは思考が始まらないため）。思考の分だけ出力枠が要るので、`max_tokens` は低 4096・中 8192・高 16000・最大 32000 です。OpenAI は `reasoning_effort` に同じ値を渡します。推論に対応しないモデル（Claude Haiku 4.5 など）が 400 を返した場合は、設定なしで自動的に呼び直します。スマホ側のログには毎回のトークン使用量（入力・出力・思考）を出しています。

## 俳句に渡す情報

時間帯が変わるたびに、その時点の情報をプロンプトへ埋め込んで詠み直します。プロンプトは設定画面で自由に書き換えられます。

| 置き換え | 例（日本語） | 例（English） |
|---|---|---|
| `{date}` `{time}` | 2026年9月6日 / 8時55分 | September 6, 2026 / 8:55 |
| `{timeofday}` | 未明・夜明け前・朝ぼらけ・朝・昼・午後・夕暮れ・薄暮・宵・夜更け | the small hours … deep night |
| `{sun}` | 日の出の3時間39分後 | 3h 39min after sunrise |
| `{daytype}` | 平日 / 休日 | a weekday / a weekend day |
| `{season}` `{sekki}` | 秋 / 処暑 | autumn / End of Heat |
| `{moon}` `{moonage}` | 下弦の月 / 23.7（夜で月が出ているときだけ） | last quarter / 23.7 |
| `{place}` | 東京都千代田区 | Chiyoda, Tokyo |
| `{feel}` | 過ごしやすい涼しさ、空気は湿って重い、風がある | comfortable coolness, the air is heavy and humid |
| `{weather_change}` | 先ほどまで降っていた雨が上がったところ（変化が無ければ文ごと省略） | the rain has just stopped |
| `{thunder}` | 雷が鳴っている / 雷は鳴っていない（下記の条件のときだけ） | thunder is sounding / there is no thunder |
| `{special}` | 【本日は中秋の名月】…（特別な日だけ） | [Today is the harvest moon] … |
| `{technique}` | 見立て――ある物を別の物として見せる。「ような」「似た」は使わない（技法名・定義・付帯ルール。毎回いずれか一つ） | seeing as: present one thing as another, without "like" or "as if" |
| `{kire}` | 中七の末尾を切れ字「や」で切る。…（毎回いずれか一つ） | a cut at the end of the second line |
| `{kigo}` | その時に使える季語の候補24語。本意を5字前後で添える（日本語のみ） | （英語では使わない） |
| `{kigo_plain}` | 同じ24語を語だけで並べたもの（既定では未使用） | （英語では使わない） |
| `{weather}` | 霧雨（今の空） | drizzle |
| `{apparent}` `{temp}` `{humidity}` `{wind}` | 22 / 20 / 91 / 8 | 同じ |
| `{rain}` | 直近1時間の降水量。ミリ | 同じ |
| `{rainsum}` | 今日ここまでの降水量の合計。ミリ（既定では未使用） | 同じ |
| `{steps}` `{activity}` | 7321 / よく歩きたる一日（既定は `{activity}` のみ使用） | 7321 / a day of steady walking |
| `{forecast}` `{tempmax}` `{tempmin}` `{pop}` | 大雨 / 23 / 20 / 96 | heavy rain / … |
| `{schedule}` | 歯医者の予定が30分後に入っています（前後1時間に予定があるときだけ） | the dentist starts in 30 minutes |
| `{recent}` | 直前に詠んだ句（最大8句） | the recent haiku |

既定プロンプトでは、体感の言葉（`{feel}`）と実測値（体感温度・湿度・風速・直近1時間の降水量・降水確率）の両方を渡します。

降水量は現在値ではなく、時間ごとの値の最新分を使います。Open-Meteo の現在値は、日本のように15分データがある地域では直近15分の量、無い地域では前1時間の量になり、同じ数字が土地によって別の意味になるためです。今日の合計（`{rainsum}`）は日付で切れて「いま」を誤らせるため、既定では使っていません。必要なら書き足せます。言葉だけだとモデルがその表現に引きずられるためです。歩数は語（`{activity}`）と実数（`{steps}`）の両方を渡します。語だけだとモデルがその表現に引きずられ、数字だけだと句にならないためです。

天気は予報の分類ではなく体感を主にしています。`{feel}` は体感温度・湿度・風速・降水から言葉を組み立てるため、同じ「曇り」でも蒸すのか肌寒いのかが句に出ます。予報の値も `{forecast}` などで引き続き使えます。

### 同じ句になりにくくする仕組み

- 直前に詠んだ句を最大8句までプロンプトに入れ、同じ語や着想を避けるよう指示しています。
- 条件を全部詠み込ませるのではなく「最も心を動かす一つか二つに絞る」よう指示しています。要素が多いほど選択肢が増え、句がばらけます。

同じ天気・同じ時間帯で続けて詠ませた例です。

```
1回目  霧雨や / 濠を渡りて / 秋の風
2回目  処暑の朝 / 石垣濡れて / 松しづか
3回目  濡れ髪や / 風に湿りの / 重き朝
4回目  休日の / 傘を返して / 秋しぐれ
```

### 時間帯の区切り

日の出・日の入りに近い時間帯は太陽を基準に、日中は時計を基準に分けます。

| 時間帯 | 区切り |
|---|---|
| 夜更け | 22:30〜4:00 |
| 未明 | 4:00〜日の出90分前 |
| 夜明け前 | 日の出90分前〜20分前 |
| 朝ぼらけ | 日の出20分前〜45分後 |
| 朝 | 〜11:00 |
| 昼 | 11:00〜14:00 |
| 午後 | 〜日の入り90分前 |
| 夕暮れ | 日の入り90分前〜20分後 |
| 薄暮 | 〜日の入り70分後 |
| 宵 | 〜22:30 |

腕時計は30分ごとにスマホへ問い合わせます。時間帯が変わっていなければ手元の句がそのまま返るため、LLM は呼ばれません。1日あたりの生成は多くて10回程度で、既定の中位モデル（Claude Sonnet 5 など）なら月あたり百数十円の見込みです。

### 決まった時刻に詠み直す

設定で「決まった時刻に」を選ぶと、朝・昼・晩に入力した時刻に詠み直します。空欄にした回は飛ばすので、1日1回から3回まで同じ欄で調整できます（全部空欄なら朝6時の1回）。時刻表は腕時計にも渡され、その分ちょうど（と次の分）にスマホへ問い合わせます。取りこぼしに備えて毎正時にも問い合わせます。

| 例 | 結果 |
|---|---|
| 朝 06:30 / 昼 12:00 / 晩 18:30 | 1日3回 |
| 朝 06:30 / 昼 空欄 / 晩 18:30 | 1日2回 |
| 朝 07:00 / 昼 空欄 / 晩 空欄 | 1日1回 |

最初の時刻より前（たとえば朝5時）は、前日の最後の句をそのまま表示します。プロンプトの時間帯や天気は詠み直した時点のものです。

### 天気の移り目と特別な日

`{weather_change}` は、現在の時間帯と3時間前を比べて「先ほどまで降っていた雨が上がったところ」「風が出てきた」のような一文にします。雨の降り出し・上がり、雲の切れ、風の強弱、気温の上下を見ています。変化が無ければ文ごと省きます。

雨についてだけは、15分ごとに更新される現在値と突き合わせ、食い違う移り目は出しません。「今まさに雨が落ちている」と「雨が上がったところ」がプロンプトに同居すると、モデルはどちらかを選んでしまい、実際と違う句になるためです。

逆に、時間ごとの降水量が本降り（2ミリ以上）なのに、いまの空は霧雨か小やみ、ということがあります。このときは「雨脚が弱まってきた」を出します。プロンプトには時間ごとの値（`{rain}`）と現在の空模様（`{weather}`）が並ぶので、何も言わないと「直近1時間の降水量は6.3ミリ」と「空は霧雨です」が矛盾したまま渡ってしまうためです。

`{special}` は中秋の名月・十三夜・元日・大晦日・節分・七夕などの日にだけ入り、「この一事を優先して主題とする」よう指示します。旧暦にもとづく中秋の名月と十三夜は月齢計算では1日ずれるため、`src/pkjs/special.js` に2030年までの日付表を持っています。それ以降は表に足してください。

### 霧と節気の名

天気の言葉は Open-Meteo の天気コードから引いていますが、コード51〜57（drizzle）を「霧雨」とは呼ばず「弱い雨」としています。「霧」の字がプロンプトに入ると、霧が出ていなくても秋霧・朝霧といった霧の季語をモデルが持ち出すためです。実際に Gemini で試すと、霧の季語は `fog` の条件で候補から正しく外れているのに、天気欄の「霧雨」から連想して「秋霧や」と詠みました。霧の字を使うのは、実際に霧が出るコード45・48だけです。

`{sekki}` の白露・処暑といった節気名もそのまま季語になるため、「二十四節気の名は日付の位置を示すために書いてあるもので、参考季語に挙がっていなければ句には用いない」と指示しています。読みが二通りある語（白露＝はくろ／しらつゆ）が多く、拍数が定まらないうえ、他の季語と重なりやすいためです。立秋のように候補として挙がっている場合は、そのまま使えます。

### 雷の扱い

雷は連想で詠まれやすいため、`{thunder}` で有無を明文化します。

- 天気コードが雷雨（95・96・99）なら「雷が鳴っている」。
- 雷ではないが荒天のとき（1時間に1ミリ以上の雨、風速8メートル毎秒以上、大雨・激しいにわか雨・強いにわか雪）は「雷は鳴っていない」。
- 穏やかな天気では触れません。晴れた日に雷の話を持ち出すと、かえって連想の種になるためです。

Open-Meteo に落雷の実測（回数や距離）はありません。CAPE などの不安定指数は取れますが、「雷の恐れ」を渡すと鳴っていない雷を詠む余地を作るため使っていません。

### 俳句の技法

既定プロンプトに【技法】の節を置き、毎回いずれか一つの技法を指定します。技法名の語は句に持ち込ませません。

技法は「型」（季語と何を並べるか）と「レンズ」（どう撮るか）の組み合わせです。型3つ×レンズ18から、成り立たない組み合わせを除いた54通りがあります。

| 型 | 内容 |
|---|---|
| 一物仕立て | 季語のものを主役にし、ほかに置くのはレンズが求めるもの（枠・光の出所・場所など）だけ |
| 同景の取り合わせ | 季語と、同じ場所で同時に一目で見えるもう一つの物 |
| 異景の取り合わせ | 季語と、別の場所の生活の中のありふれた物。二つのつながり（理由・因果・感想）は書かない |

| 分類 | レンズ |
|---|---|
| 構図・空間 | ズームイン / ズームアウト / 垂直チルト / 水平パン / 額縁・透過 / 奥行 |
| シャッター | 高速静止 / モーション / タイムラプス / 予兆 / 痕跡・不在 |
| 現像・質感 | 映り / 色彩 / 明暗 / 共感覚 / マテリアル / ミクロ / 微音 / 擬音 |

- 組み合わせごとに、指定文を一つの文として書いてあります（`src/pkjs/technique.js` の `LENSES`）。型とレンズの文を単純に足すと、条件が重なって崩れるためです。
- 一物仕立て×水平パン（二物を横に並べられない）、異景の取り合わせ×共感覚（飛躍が重なって意味が通らなくなる）、一物仕立て×痕跡・不在（季語を描かずに季語一つを詠むことになる）は除いています。
- 一物仕立てのズームアウトは「季語の一部分から季語全体へ引く」形です。引いた先を周りの景にすると、その景が別の物になり一物仕立てとぶつかったためです。
- 句のどこに置くか（上五に〜）は指定しません。天気で組み合わせを絞ることもしません。
- 各レンズには、狙いを説明してしまう語の禁止を添えています（ズームインの「見る」「覗く」、予兆の「今にも」「寸前」など）。
- 物として描けない時候の季語（暖か・春昼など）は、レンズが許す組み合わせ以外では季語の候補から外します（`noJiko`）。
- 水平パンの異景の取り合わせと一物仕立てのズームアウトでは、空と天気の季語（月・雷・雪など）も候補から外します（`noTenmon`）。地上の物と横に並べられず、一部分から全体へ引くこともできないためです。同景の取り合わせでは、季語を並べる二つの物に入れず「季語の景の中の二つの物」とします。
- 水平パンは5通りの言い方を試しましたが、技法の平均は1前後から大きくは動きませんでした。十七音では横への目の動きが読み取りにくく、審査も割れやすいレンズです。「名詞二つだけ」のように言い回しを縛ると、かえって三つ目の物や修飾を足すため、物の数だけを決めています。
- 先にレンズを選び（直近6回に使ったレンズは避ける）、次に型を選びます。

切れの型は、型に合わせて絞ります（`avoidKire`）。

| 型 | 使う切れ |
|---|---|
| 一物仕立て | 「かな」か切れ字なし（句中の「や」で二つに割らない） |
| 同景・異景の取り合わせ | 上五か中七の「や」か切れ字なし（「かな」で一つにまとめない）。異景の取り合わせの「や」は季語に付ける |

「けり」は動作を言い終えるか動詞で終わるため、どの型でも使いません。レンズ側でも、ズームアウトは上五の「や」（目の動きが途切れる）を、高速静止とモーションは「かな」（止まった感じや動きが詠嘆で緩む）を避けます。

省略（誰がいるのか・誰がしたのか・その後どうなったか・どう感じたか・なぜそうなったかを言わない）は選択肢にせず、【作句】で常に守らせます。人を出すことまでは禁じず、人は物や動作の跡で示させます。

指定文は `test/technique_sweep.js` で詠ませて採点して詰めています（`--per 3` で各組み合わせに3場面ずつ割り当てる）。2026年10月の比較では、詠み手のモデルで結果が大きく変わりました（審査は Sonnet 5.5）。

| 詠み手 | 出来 | 技法 | 基準（出来3以上・技法2）を満たした組み合わせ |
|---|---|---|---|
| Haiku 4.5（3句ずつ、審査も Haiku） | 1.90 | 0.59 | 0 / 55 |
| Sonnet 5.5 low（3句ずつ） | 2.70 | 1.41 | 8 / 55 |
| Opus 5.5 low（1句ずつ） | 2.87 | 1.76 | 38 / 55 |

Haiku では季節違いの季語・破調・切れ字の指定違反が多く、技法以前で崩れます。

切れの型も毎回一つを指定します（`{kire}`）。`src/pkjs/kire.js` が呼び出しのたびに次の五つから無作為に選びます。直近2回に使った型は避けるので、同じ切れ方が続きません。

| 型 | 指定 |
|---|---|
| 上五や | 上五の末尾を「や」で切る |
| 中七や | 中七の末尾を「や」で切る |
| かな | 下五の末尾を「かな」で結ぶ |
| けり | 下五の末尾を「けり」で結ぶ |
| 切れ字なし | 切れ字を使わず、名詞止めや句中の間、二物の取り合わせで切る |

同じ条件で10回詠ませた比較です。技法の指定で句がはっきりばらけました。

| | 上五の種類 | 異なり語数 |
|---|---|---|
| 技法の指定なし | 5 / 10 | 21 |
| 技法を毎回指定 | 9 / 10 | 34 |

### 季語の候補を渡す

同じ季語ばかりになるのを防ぐため、その時に使える季語の候補を毎回プロンプトに載せます（日本語のみ）。

- もとにしたのは、きごさい歳時記の「基本季語700」です。687語を、季節・時期（初秋・三秋など）・分類（時候・天文・地理・生活・行事・動物・植物）・読みの拍数とともに `src/pkjs/kigo.js` に持っています。さらに、同じ歳時記の全季語一覧（`data/kigosai_all.txt`）から、本意を添えなくても取り違えようのない、いまの暮らしで見聞きする名詞（チューリップ・扇風機・台風・白菜など）を259語足して、計946語にしています。行事・忌日・七十二候や、廃れた風俗・病名（コレラなど）、「秋の山」のような季節＋の＋名詞の語は足していません。冬桜・春休・秋日和のように一語として定着したものは足しています。
- 二十四節気からその日の時期区分を求め、合う季語だけを選びます。処暑なら初秋と三秋です。
- 時間帯に結びつく季語は、その時間帯にだけ出します。「秋の灯」「月」は夜、「秋暁」は朝、といった具合です。
- 天気に結びつく季語は、実際にその事象があるときだけ出します。雨が降っていなければ「秋の雨」は候補に入らず、雷雨でなければ雷の季語も入りません。晴れ・曇り・風・霜・冷え込み・雨上がりも同じように見ます。
- 逆に、本意に反する天気のときは候補から外します。降っている間の「秋の水」「水澄む」「鰯雲」「秋の空」、風のある夕の「夕凪」などです。鰯雲は晴れ間のある高い空の雲で、本降りの空には出ないためです。表では天気条件の頭に `!` を付けて書きます（`秋の水` なら `!rain`）。雨の日に水たまりを見て「秋の水」と詠む、といった取り違えを防ぐためです。
- 天気が取れないときは、天気に依る季語を出しません。降っていないと言い切れないため、`!` の付いた語も同じく外します。
- 語には本意――その語で詠むべき情感や景――を5字前後で添えます。桐一葉なら「衰えの兆し」、水温むなら「春の訪れ」、冬至なら「陽の返る日」です。字面どおりで含みの無い語（立春・春昼）には何も付けません。ただし「春の日」「冬の夜」のような季節の＋名詞には必ず付けます（春の山＝霞む穏やかな山、秋の日＝澄んで短い日ざし）。本意が無いとどんな景にも付けられる語になるためです。ただし本意を付けても、これらの語が選ばれる頻度は下がりませんでした（静かな2場面・各20句で、付ける前 2/20、付けた後 6/20）。頻度を決めているのは候補の組み立てで、分類ごとに1語ずつ順に取るため語数の少ない時候・天文・地理の語が候補に入りやすく、季節の＋名詞はその3分類に集まっています（表では5%、候補24語の中では15〜21%）。
- 何であるかの説明は書きません。読むのは人ではなくモデルで、蟷螂がかまきりであることは知っているため、同定に字を使ってもプロンプトが長くなるだけだからです。例外は二つで、景そのものを言わないと取り違える語（秋の水＝澄んで冷たい川や池）と、字面が別の季節や別の物に見える語（麦の秋＝初夏の黄金、初潮＝仲秋の大潮）です。
- 6拍以上の季語には「中七のみ」と印を付けます。上五・下五には収まらないためです。
- 候補は分類ごとに無作為で選び、並びも毎回変えます。順番を固定すると、モデルが先頭の語にばかり寄るためです。
- 直近の8句（`{recent}` に渡すのと同じ句）で使った季語は候補から外します。「直前の句と同じ季語は避ける」という指示だけに頼らず、候補の段階で外しておくためです。句の文字を表と照らして拾い、長い語から見るので「秋の水」を「秋」とは数えません。仮名書き（ひぐらし＝蜩）や送り仮名の違い（落ち葉＝落葉）も拾います。外すと一語も残らないときは外しません。

同じ条件で10回詠ませた比較です。候補を渡すと使う季語の種類が増えました。

| | 使われた季語の種類 |
|---|---|
| 候補なし | 2（処暑・残暑） |
| 候補あり | 5（秋の雨・残暑・秋の声・秋気・新涼） |

### 季重なりの検査

生成された句（日本語）は、季語がいくつ入っているかを確かめてから腕時計に送ります。照合に使うのは候補の表だけでなく、きごさい歳時記の全季語（約5200語、`src/pkjs/kigo_all.js`）です。蝶・椿・汗・風鈴のように、候補に出していない動植物や暮らしの語をモデルが季語と気づかずに置くことがあるためです。季語が二つ以上あれば、重なった季語の名を添えて一度だけ詠み直させます。二度目の句は重なっていてもそのまま使います。

照合は長い語から当て、当たった所を伏せていきます（秋の水 の中の 秋 や 水 は数えない）。送り仮名や「の」の違い（落ち葉＝落葉、秋の風＝秋風）、歴史的仮名遣い（山笑う＝山笑ふ）も同じ語として扱います。桜色・藤色のような色の名、3字以下の仮名だけの語（はえ・だし など、ふつうの言葉に紛れる）、動詞の一部になりやすい字（忍・茂・踊）、一年中使う語（今年・去年）、色名としての橙は数えません。

`src/pkjs/kigo_all.js` は `python3 tools/build_kigo_all.py` が `data/kigosai_all.txt` から作ります。一覧を差し替えたときはスクリプトを流し直してください。`data/kigosai_all.txt` は歳時記サイトの一覧を貼ったものなので、リポジトリには含めていません。

季語の表を差し替えたい場合は `src/pkjs/kigo.js` の行を編集してください。1行が `語｜拍数｜季節｜時期｜分類｜時間帯｜天気条件｜本意` です。読みで拍数が変わる語は `紅葉:もみじ` `紅葉:こうよう` のように読みを付けて行を分け、それぞれの拍数を持たせます（候補には「紅葉（もみじ）」のように読みを添え、同じ語は一つの読みだけを載せます）。別の読みでは季語でなくなる語（菖蒲:しょうぶ、初日:はつひ）は季語の読みだけを書きます。読みが違っても拍数が同じ語（河豚・蟷螂）には付けません。天気条件に書けるのは `rain` `snow` `frost` `cold` `clear` `cloud` `wind` `fog` `thunder` `afterrain`（直近3時間に降った）で、頭に `!` を付けるとその事象が起きていないときだけ出します。

### 季語について

既定プロンプト（日本語）は、冒頭の一文（ウォッチフェイス用に今の状況を想起させる俳句を一句作る）のあと【状況】【避ける】【作句】【切れ】【季語】【技法】【形式】の各節に分けています。状況には実測値（気温・湿度・風速・降水量・歩数）を入れず、体感や天気の言葉だけを渡します。作句では、心が動く一、二点に絞り具体を一つ置いて像で示す、視覚・聴覚を主とし体感語や内面の語は使わない、動詞は一つまで、場所は地形・構造・物で示す、文語の活用を崩さない、状況の表現を直接使わない、修飾を重ねて景を絞り込まない、誰が・その後・感情・因果を言わず人は物や動作の跡で示す、を指示します。切れは `{kire}`、技法は `{technique}` で毎回一つずつ指定します。形式では五七五を拍で数え、縦書きに収まるよう各行7文字以内とし、常用漢字だけを使わせます。句の履歴がまだ無いときは、【避ける】の節が見出しごと落ちます。

季語については、`{season}` の季語を一つだけ入れ、動植物の名も含めた季重なりに注意させます。歳時記の本意どおりに使う、季語がそれ自体で含む動作（鳴く・咲く等）は書かない、別の季語に替えても成り立つなら採らない、「季節＋名詞」型は避ける、とも指示します。候補に添えた本意・拍数の注記は句に入れないことも明示しています。技法名を句に出させないのと同じ理由です。気象の季語は状況の範囲内から選ばせます。強い風と強い雨から嵐を思い、雷が鳴っていないのに遠雷（夏の季語）を詠む、といった連想を防ぐためです。

### 使う漢字について

日本語の既定プロンプトでは、漢字を常用漢字に限るよう指示しています。腕時計の日本語フォント（言語パック）に含まれない漢字は □ で表示されるためです。プロンプトを書き換える場合もこの一文は残すことをおすすめします。

### 取得できない情報の扱い

天気・地名・歩数のいずれかが取れないとき、または設定でオフにしたときは、その語を含む文がプロンプトから自動的に取り除かれます。置き換えが文字列として残ることはありません。

### 月を入れる条件

月の文は、次の全てを満たすときだけ入ります。

- 夜の時間帯であること（夕暮れから朝ぼらけの前まで）。昼間の句に月が混ざりません。
- 新月の前後でないこと（月齢 1.5〜28）。
- 月が地平線の上にあること。月の出は「日の出の時刻 ＋ 月齢 × 約49分」、出てから約12.4時間で沈むという近似で判定します。上弦の月は深夜には沈み、下弦の月は夜更けにならないと出ない、といった違いが反映されます。境目では1〜2時間ずれることがあります。
- 雲量が9割未満であること（天気が取れている場合）。

### 予定を句に入れる

設定画面にカレンダーの iCal（ICS）URL を入れると、`{schedule}` にいまの前後1時間の予定が1件だけ入ります。Google カレンダーなら「設定 → カレンダーの設定 → カレンダーの統合 → 非公開URL（iCal形式）」の URL です。

- 入る文は3通りです。開催中なら「◯◯の予定中です」、これからなら「◯◯の予定が30分後に入っています」、終わった直後なら「◯◯の予定が終わってから25分後です」。
- 既定プロンプトには日本語・英語とも `{schedule}` の文が入っています（英語は `On the calendar, {schedule}.`）。設定画面で保存したプロンプトにも、既定文の変更は起動時に自動で入ります（「プロンプトの編集」参照）。
- 予定の件名がそのまま LLM に渡ります。人に見せたくない件名がある場合は、この設定を空欄のままにしてください。
- 前後1時間に予定が無いとき、URL が空のとき、取得に失敗したときは、`{schedule}` を含む文ごと落ちます。句作りは止まりません。
- 終日予定（`VALUE=DATE`）と繰り返し予定（`RRULE` / `RDATE` / `RECURRENCE-ID`）は使いません。毎日の定例で句が埋まらないようにするためです。
- 開催中の予定を先に選び、次にいまへ近い予定を選びます。同時に複数あっても句に入るのは1件だけです。
- 時刻はスマホのローカル時間として扱い、末尾が `Z` の値だけ UTC から直します。`TZID` は見ないため、スマホと暦の時間帯が違うとその差だけずれます。
- 取得は句を詠むときだけで、20秒で諦めます。

### いま表示している句の確認と解説

設定画面の先頭に、いま腕時計に出している句、詠んだ日時、使った LLM とモデル、最近の句（最大7句）、そのとき使ったプロンプト（折りたたみ）を表示します。

「この句の解説を読む」ボタンを押すと、句と、詠ませたときのプロンプトを LLM に渡して解説を書かせ、その場に表示します。季語と季節感、切れや音の運び、情景と余情、工夫している点を300字以内（英語は150語以内）でまとめます。設定画面で選んでいる LLM・キー・モデル・思考の深さを使い、通信はスマホから直接行います（腕時計は介しません）。見本は `screenshots/config_page_explain.png` です。

### プロンプトの編集

- 設定画面のプロンプト欄は複数行で表示・編集できます。
- 欄を空にすると既定のプロンプトが自動で入ります。「既定に戻す」ボタンでも戻せます。
- 空欄のまま保存した場合も、既定のプロンプトが保存されます。
- 既定のプロンプトを直した版に上がると、保存してあるプロンプトにも起動時にその変更が入ります。手元の文がどの既定から来たかを覚えておき（`prompt-base`）、既定で変わった行だけを差し替えます。自分で書き換えた行はそのまま残ります。既定を直すときに別の作業は要りません。仕組みは `src/pkjs/prompts.js` にあります。
- 設定画面の見本は `screenshots/config_page_1.png` から `config_page_3.png` にあります。

## 短冊の右の表示

日本語表示の Pebble Round 2（gabbro）と Pebble Time 2（emery）では、短冊の右に朱の丸印と漢数字で一つの情報を出せます。Time 2 では表示を有効にすると短冊を 30px 細くして列を空けます。ほかの機種は右に余地がないので出しません。

| 設定 | 印 | 下の文字 |
|---|---|---|
| 電池 | 電 | 残量を一割単位で「八分」。満充電は「十分」 |
| 天気・気温 | 晴・曇・雨・雪・霧・雷・嵐 の一字 | 現在の気温「十八度」。氷点下は「零下三度」 |
| 歩数 | 歩 | 今日歩いた道のりを一里（約3.9km）の半里刻みで「一里半」。半里に満たなければ「半里未満」 |

- 天気は Open-Meteo の現在の天気（WMO コード）を一字にします。大雨・激しいにわか雨・強く凍る雨は「嵐」にしています。腕時計が毎時15分にスマホへ頼んで取り直します（30分以内に取った天気があればそれを使う）。句を詠むときに取った天気も使います。
- 歩数は Pebble Health の歩いた距離を使い、取れなければ歩数×0.7m で換算します。
- 長い文（零下十八度など）は小さい字に切り替えて収めます。
- 見本: `screenshots/gabbro_ja_side_weather.png`・`gabbro_ja_side_steps.png`・`emery_ja_side_battery.png`

## 背景の切り替え

- 既定では、スマホの位置情報から当日の日の出・日の入り時刻を計算し、その時刻を境に背景を切り替えます。計算は NOAA の簡易式（`src/pkjs/sun.js`）で、誤差は数分程度です。
- 日の出・日の入り時刻は俳句と一緒に腕時計へ送られ、腕時計側に保存されます。日付が変わると取り直します。
- 位置情報が取得できない場合や、高緯度で日の出・日の入りが無い日（白夜・極夜）は、自動的に固定時刻の判定に切り替わります。
- モノクロ機種は日中が白背景・黒い筆、夜間が黒背景・白い筆になります。
- 腕時計を軽く叩くと、その場で今日の句と日の出時刻を取り直します（1分に1回まで）。

## 動作の仕組み

- スマホ側 JS（`src/pkjs/index.js`）が「今の時間帯の句」がキャッシュにあるか確認し、無ければ天気を取得してから LLM に生成を依頼します。
- 生成結果は 3 行に整形（Markdown 記号や句読点を除去）して AppMessage で腕時計に送ります。
- 腕時計側 C（`src/c/haiku.c`）は句と日の出・日の入り時刻を永続ストレージに保存し、毎正時と日付変更時に JS へ問い合わせます。時間帯が変わっていなければ手元の句がそのまま返るため、LLM は呼ばれません。
- API キーはスマホ側の localStorage にのみ保存され、腕時計には送りません。天気と地名の取得に API キーは不要です。
- LLM に送るのは市区レベルの地名だけで、緯度経度は送りません。地名が不要なら設定でオフにできます。
- 予定はスマホから ICS の URL を直接取りに行き、句に使う1件の件名だけを LLM に渡します。URL が空なら取得しません。
- 歩数は腕時計から Pebble Health の当日の合計だけを受け取ります。取得できない機種では歩数の文が落ちます。
- Claude では Opus 5 / Fable 系モデルを指定した場合、安全分類器による拒否時にサーバー側で別モデルへフォールバックする設定（`fallbacks: "default"`）を付けています。

### 条件を変えて句を作らせ、傾向を見る

`test/scenes.js` は日時・天気・場所を差し替えてプロンプトを組み立てます。場面は「冬の朝・山あいの盆地」「冬の雪・雪国」「春の霞む朝・甲府盆地」「夏の夕立・海べり」「秋の月夜・高原」「秋の晴れた昼・城下町」「春の穏やかな夕・古都」の7つで、ファイル冒頭の `SCENES` を書き換えれば足せます。地名だけは実際に引くので、本物の市町村名が入ります。

LLM を実際に呼ぶ場合です。

```
node test/scenes.js --key-file ~/gemini-key --n 2
```

数をまとめて詠ませて傾向を見るときは、サブエージェントに詠ませます。API キーが要りません。

```
node test/scenes.js --dry --n 10      # test/out/prompts に50本のプロンプト
```

書き出したプロンプトを `haiku-poet` サブエージェント（`.claude/agents/haiku-poet.md`、Sonnet・effort medium）に場面ごとに渡し、結果を `test/out/scene<N>.json` に書かせます。このエージェントは「プロンプトを渡された LLM」として振る舞うだけで、プロンプトを直したり批評したりしません。そのあと集計します。

```
python3 test/analyze.py
```

季語が入っているか、候補から選んだか、季重なり、季節のまたがり、本意の写り込み、7文字超、切れ字の重複を数え、使われた季語の種類と句に出た漢字（常用外の確認用）を並べます。仮名で書かれた季語（かたつむり＝蝸牛）や送り仮名の違い（落ち葉＝落葉）も照合します。仮名の対応表は `src/pkjs/kigo.js` の `ALIAS` にあり（直近の句の季語を候補から外す照合と共用）、`analyze.py` はそれを読み込んでいます。取りこぼしに気づいたら `kigo.js` 側に足してください。

50句での実測（2026年9月）は、季語あり 50/50、候補から選んだ 42/50、季重なり 1、季節またぎ 0、7文字超 0、切れ字の重複 0、使われた季語29種でした。強い事象があるとき（雪・雷・月）は候補より事象そのものを詠み、穏やかな日ほど候補から広く選ぶ傾向が出ています。

## エミュレータに日本語フォントを入れる

言語パック（.pbl）は `pebble fw` で送れます。適用後に時計側が再起動し、その際にエミュレータの JS ランタイム（pypkjs）が落ちることがあるため、スクリーンショットは qemu に直接つないで撮ります。

```
# 1. アプリを入れた状態で言語パックを転送する（応答遅延の警告が出ても適用されていることがある）
pebble fw --emulator basalt install-lang path/to/ja_JP.pbl

# 2. 落ちたエミュレータを起こす（フラッシュ qemu_spi_flash.bin は消さないこと。言語パックはそこに残る）
pkill -9 -f qemu-pebble; pkill -9 -f pypkjs; rm -f /tmp/pb-emulator.json
pebble ping --emulator basalt

# 3. qemu のポートを調べ、直接つないで時刻設定とスクリーンショット
python3 -c "import json;print(json.load(open('/tmp/pb-emulator.json'))['basalt']['4.9.148']['qemu']['port'])"
pebble emu-set-time --qemu localhost:<port> 12:00:50
pebble screenshot --qemu localhost:<port>
```

言語パックを入れた後は `pebble install` でアプリを再起動すると pypkjs が落ちやすいので、設定を変えたいときはエミュレータを止めてから `~/.pebble-sdk/<sdk>/<platform>/localstorage/` の保存内容を書き換え、`pebble ping --emulator <platform>` で起動し直すのが確実です。basalt / chalk / diorite / emery / gabbro の5機種で、Pebble Time 用の言語パックがそのまま使えることを確認しました。
